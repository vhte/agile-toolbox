Forecast from finished work, not from estimates

Flow Forecaster turns a CSV export from Jira, Linear, GitHub or any tracker into cycle time percentiles, throughput, WIP and aging work, so you can see where items actually wait. It then runs a Monte Carlo simulation on your own history to answer "how many by this date?" and "when will these be done?" as ranges with a confidence level.

Everything stays in this browser. Nothing is uploaded.

Data and columns
Paste an export, or use "Open CSV file". Comma, semicolon and tab delimiters are detected automatically.

Map a start and a done column to a dataset with at least one valid row to see metrics.

Cycle time

Cycle time is counted in calendar days from start to done, inclusively: an item started and finished on the same day took 1 day (the Kanban Guide and ProKanban convention). Percentiles use the nearest-rank method: sort the cycle times and take the value at position ceil(p × n). "85%: 9 days" reads as "85% of finished items took 9 days or less".

Throughput per week

Items finished per ISO week (Monday to Sunday), including weeks where nothing finished.

Work in progress

An item counts as WIP on every day from its start to its done date, inclusive, which keeps this chart consistent with the cycle time convention.

Aging work in progress

0

Age counts like cycle time (start to the as-of date, inclusive). Amber: older than 70% of everything finished. Red: older than 85% of everything finished. Swarm on the red ones first.

Segments

Tag items as "agent-assisted" or "human" (a label or a custom field) and compare them here. AI agents tend to raise code volume while review and coordination become the bottleneck, so judge them on end-to-end cycle time of finished items, not on coding speed.

Monte Carlo forecasts

10,000 simulated futures, each day drawn at random from your daily throughput inside the history window (zero days included). It needs at least about 10 finished items in the window to say anything useful.

How to use this

This tool follows the flow metrics of the Kanban Guide (ProKanban.org) and Daniel Vacanti's When Will It Be Done?: cycle time, throughput, WIP and work item age, plus Monte Carlo forecasting instead of story-point promises.

  • Export finished and unfinished items with a start date and a done date. In Jira, "Created" and "Resolved" work, but Created measures lead time; a date for when work really started (a "Start date" field, or the "In Progress" transition date) gives true cycle times. Linear: "Started" and "Completed", with "Canceled" mapped so canceled work is left out. GitHub: "created_at" and "closed_at". To keep only some rows (for example one status or issue type), map that column as the segment and pick it in the segment filter.
  • Set the as-of date to the day the export was pulled. It defaults to today, which is right for a fresh export; ages and forecasts are measured from it.
  • Read the 85th percentile as your service level expectation: "85% of our items finish within N days". Bring it to refinement to spot items that are too big before they start.
  • Walk the aging list in the Daily Scrum or standup, oldest first. An item already older than your P85 is a conversation about help, splitting or unblocking, not about blame.
  • Check Little's Law (average WIP = throughput × cycle time). When predicted and actual cycle time drift far apart, the system is not stable: WIP is growing or items are being abandoned, and forecasts will be optimistic.
  • Forecast with ranges. For "how many by a date", 85% confidence means 85% of simulated futures finished at least that many items (the 15th percentile of totals). For "when", it is the date by which 85% of futures were done. Re-forecast whenever the data changes, not once per quarter.
  • Compare segments (type, or a label like "agent-assisted" vs "human") to check whether a change in how you work actually moved end-to-end cycle time.

This tool deliberately never breaks data down by person. Assignee, reporter and similar columns are ignored on import, because flow is a property of the system, and per-person numbers turn into performance reports.
