Write work items a teammate or an AI agent can actually finish.

How to use this

A brief is the spec in spec-driven development: when a person or a coding agent picks up a work item, the quality of what comes back is capped by the quality of what went in. The checks combine Bill Wake's INVEST criteria (Independent, Negotiable, Valuable, Estimable, Small, Testable) with a lightweight Definition of Ready.

  1. Write the goal first. Who benefits and what changes for them. If you cannot say why, the executor cannot make good small decisions on your behalf.
  2. Write acceptance criteria in a Three Amigos conversation (product, development, testing). The Given / When / Then helper follows BDD's Gherkin shape. Every vague word the checker flags is a review argument waiting to happen.
  3. Say how to verify. Tests to run, commands, manual checks. For an agent this is mandatory: it is how the agent proves its own work and how the reviewer avoids rereading the whole diff.
  4. State what is out of scope. Agents widen scope to be helpful; people do too. One line prevents a surprise refactor.
  5. Pick a risk tier and an executor. High risk means a second human reviewer and an agent that only drafts. Pair (person + agent) is the safe default when in doubt.
  6. Treat warnings as conversation prompts, not gates. A Definition of Ready used as a hard gate turns into bureaucracy. The aim is a shared understanding, then paste the Markdown into your tracker or the agent prompt into your coding agent.

Everything stays in this browser. Nothing is sent anywhere.
