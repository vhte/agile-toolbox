Working agreements, written by the team

Write down how your team works together, including how you use AI tools and coding agents, one agreement at a time. Check consent with Fist of Five, then export a team agreement for the wall and an AGENTS.md file for your repository.

      How to use this
      

        
    
          
  1. Work section by section. Read the prompt questions aloud and let people write silently for two minutes before anyone speaks (the "1-2-4-All" pattern from Liberating Structures). Suggestions are a starting point: add one, then rewrite it in the team's own words.
    2. 
          
  2. Check consent with Fist of Five. Everyone shows 0 to 5 fingers at the same time. Tap how many people showed each value; no names are recorded. With the default rule, an item is agreed when nobody shows 0 or 1. If it fails, ask "what would make it a 3 for you?", edit the wording and check again. This is consent, not consensus: "good enough for now, safe enough to try", as sociocracy puts it.
    3. 
          
  3. Write down your AI stance. DORA's 2025 AI Capabilities Model names a clear and communicated AI stance as a foundation for AI helping delivery rather than hurting it. Agree which tools are approved, what never goes into a prompt, and who is accountable for generated code.
    4. 
          
  4. Hand the rules to your agents. The AGENTS.md tab turns agreed AI and code review items into Boundaries (Always, Ask first, Never) next to your build and test commands. Commit the file at the root of the repository.
    5. 
          
  5. Revisit. Working agreements (as described by Esther Derby and Diana Larsen in "Agile Retrospectives") only work if they stay alive. Review them every quarter or when the team changes, and drop what nobody follows.
